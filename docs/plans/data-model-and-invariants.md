# MVP 資料模型與不變式

本文件把 `CONTEXT.md` 的既定產品語意轉成概念模型、資料所有權與可由資料庫驗證的限制。它不是 migration、ORM schema 或模組 API；實作時 `supabase/migrations/` 仍是唯一 schema 真本。

## 範圍

本模型涵蓋遊戲、外部來源、名稱、平台、自由標籤、來源分類、貢獻者、人數、資源回收與 BGG 最新指標。

媒體上傳、筆記、清單成員、庫外引用轉正的詳細狀態轉移與封存／軟刪除，分別由「將既有媒體規則落成縮圖與上傳狀態機」及「將既有筆記、清單與刪除規則落成狀態機」定稿。本文件只為它們保留共用的外部遊戲身分。

## 概念與資料所有權

| 概念 | 身分與責任 | 可寫入者 |
|---|---|---|
| 遊戲條目 | 收藏庫的主要單位；保存使用者擁有的資料與資源回收狀態。 | 擁有者操作的應用程式流程。 |
| 外部遊戲身分 | 一筆 `供應商＋來源 ID`，保存該外部遊戲的快照及來源關係。可獨立存在，供庫外引用使用。 | 建立、連結或重新整理的來源 adapter。 |
| 使用者資料 | 自訂顯示名稱、實際平台、自由標籤、手動貢獻關係及後續票處理的筆記、媒體、連結、清單。 | 擁有者操作的應用程式流程。 |
| 來源資料 | 原文名稱、別名、介紹、年份、來源封面、來源分類、來源貢獻關係、來源人數與來源支援平台。 | 來源 adapter；重新整理可替換此資料。 |
| 資源回收項目 | 同一遊戲條目的生命週期狀態，不是第二種遊戲或資料副本。 | 移入資源回收區與還原流程。 |

## 關係圖

```text
                         ┌──────────────────────────────┐
                         │ 外部遊戲身分                 │
                         │ provider + source_id（唯一） │
                         │ medium、來源快照             │
                         └──────────────┬───────────────┘
                                        │ 0..1
                         已加入收藏庫   │
                                        ▼
┌───────────────┐              ┌──────────────────┐
│ 庫外清單引用   │─────────────▶│ 遊戲條目         │◀────────┐
│ （後續票定義） │ 以外部身分解析│ medium、trashed  │         │
└───────────────┘              └───┬────┬────┬─────┘         │
                                  │    │    │               │
          ┌───────────────────────┘    │    └──────────────────┐
          ▼                            ▼                       ▼
   遊戲名稱（多筆）            實際平台／自由標籤      手動貢獻關係
                                    │                       │
                                    ▼                       ▼
                             共用平台／共用標籤          貢獻者

外部遊戲身分 ── 來源分類／來源貢獻關係／來源人數／BGG 最新指標
```

「外部遊戲身分」是庫外引用與正式遊戲條目的共同錨點；它不是跨供應商、跨媒介或同名作品的合併主體。

## 核心實體與關係

### 遊戲條目與外部遊戲身分

- `games`：主鍵、`medium`（`board_game` 或 `video_game`）、`trashed_at`，以及對外部遊戲身分的可空連結。手動最小條目一開始沒有這個連結。
- `external_game_identities`：主鍵、`provider`、`source_id`、`medium` 與來源快照。來源快照包含來源原文名稱、別名、介紹、最早發行年份、來源封面、來源人數、來源支援平台與其他由來源管理的資料。
- 一個外部遊戲身分最多連到一個遊戲條目；一個已連結遊戲條目恰好連到一個外部遊戲身分。外部遊戲身分可在尚未加入收藏庫時獨立存在。
- `external_game_references`（由清單票細化）指向 `external_game_identities`，而不是複製 `provider` 與 `source_id`。若外部身分已有遊戲條目，讀取端解析為該遊戲；若沒有，才顯示庫外引用資料。

### 名稱、平台與自由標籤

- `game_names`：一個遊戲可有自訂顯示名稱、來源原文名稱、來源在地化名稱與別名。顯示名稱優先順序由自訂名稱覆蓋來源名稱；名稱從不作為硬性去重鍵。
- `platforms`：全庫共用，保存首次建立時的顯示名稱、比較用正規化名稱與系統／自訂屬性。`game_platforms` 只表示擁有者實際使用的電子遊戲平台。
- `tags`：全庫共用，保存顯示名稱與比較用正規化名稱。`game_tags` 為多對多關係；來源資料不得寫入這些資料列。
- `external_supported_platforms`：IGDB 來源支援的平台資料，與 `game_platforms` 分開保存，僅作為參考。

### 來源分類、貢獻者與人數

- `source_categories`：以 `provider＋category_kind＋source_category_id` 識別；`external_game_categories` 把它連到外部遊戲身分。未知來源種類不建立可篩選資料。
- `contributors`：全庫共用的人物或組織。手動建立者沒有來源身分；匯入者以 `provider＋source_id` 識別。同名只用於提示，絕不作為合併依據。
- `source_contributions`：外部遊戲身分、貢獻者、固定角色（設計／開發、美術、發行）的來源關係。重新整理只取代此集合。
- `manual_contributions`：遊戲條目、貢獻者、固定角色的手動關係。重新整理不得讀取、改動或刪除它。
- `external_player_profiles`：外部遊戲身分的一對一來源資料，含同地多人最小／最大人數與單人支援狀態。`games.player_count_note` 是擁有者可寫的補充，不能被來源重新整理覆寫。

### BGG 最新指標與資源回收

- `bgg_current_metrics`：以 BGG 外部遊戲身分為鍵，保存最新重度、Strategy Game Rank 與最後成功更新時間；沒有歷史列。
- 移入資源回收區只寫入 `games.trashed_at`，不改寫外部遊戲身分、來源資料、使用者資料或任何 Storage 關聯。還原清除該欄位。

## 可驗證不變式

### 外部身分與媒介

1. `external_game_identities(provider, source_id)` 全域唯一，且不因遊戲移入資源回收區而釋放。
2. `games.external_game_identity_id` 在非空時唯一；因此同一來源遊戲不能同時建立兩筆一般或資源回收中的遊戲條目。
3. 外部遊戲身分的 `medium` 必須與所連遊戲條目的 `medium` 相同。BGG 只能連桌遊；IGDB 只能連電子遊戲。
4. 名稱相同、正規化名稱相同、相似名稱、改編關係或同一系列，都不能建立外部身分的合併規則。
5. 來源更換不屬 MVP：一旦遊戲連到外部遊戲身分，不提供改接到另一筆外部身分的寫入路徑。

### 使用者資料與來源資料

1. 來源 adapter 只能寫入來源快照與來源關係；不得覆寫自訂顯示名稱、實際平台、自由標籤、手動貢獻關係，或後續票管理的筆記、媒體、附件、連結與清單。
2. 來源資料重新整理必須以單一來源身分為範圍替換；若寫入失敗，舊快照保持可讀。
3. 手動最小條目的人數結構化值為未知；只有來源連結成功後才能寫入來源人數資料。

### 共用分類與貢獻者

1. `platforms.normalized_name` 與 `tags.normalized_name` 各自唯一；正規化只處理前後空白及英文字母大小寫，保留第一次建立的顯示名稱。
2. 系統預設平台不可改名或刪除；自訂平台與自由標籤只在沒有任何一般或資源回收遊戲關係時可刪除。
3. `source_categories(provider, category_kind, source_category_id)` 唯一；相同名稱但不同來源種類必須保留為不同分類。
4. 匯入貢獻者只依相同 `provider＋source_id` 去重。不同來源身分或無來源身分的同名貢獻者保持分開。
5. 貢獻角色僅能是設計／開發、美術、發行。來源貢獻關係唯讀；手動關係可新增或移除，兩者互不覆寫。

### 人數、BGG 與生命週期

1. 同地多人最小值與最大值必須同時存在或同時為空，且最小值不得大於最大值。
2. 單人支援只能是支援、不支援或未知；重度只能是 1 到 5 的小數或空值；Strategy Game Rank 只能是正整數或空值。
3. BGG 每日更新只讀取未移入資源回收區且已連結 BGG 外部身分的遊戲；失敗保留舊值與最後成功時間。
4. 資源回收區不是刪除：MVP 不存在永久刪除轉移，任何關聯的外部身分與使用者資料均不得在移入資源回收區時級聯刪除。

## 重要情境

### 庫外引用轉正

1. 清單加入 BGG 搜尋結果時，建立或取得該結果的外部遊戲身分，庫外引用指向它。
2. 使用者之後以同一 BGG 結果加入收藏庫時，在同一交易內建立遊戲條目並連到既有外部遊戲身分。
3. 清單不必搬移成員關係；讀取時因外部遊戲身分已有遊戲連結而解析為正式遊戲條目。
4. 若該身分已連到資源回收遊戲，建立與連結流程必須拒絕重複並要求還原。

### 《Barrage》桌遊與 Steam 版

```text
BGG:Barrage ──→ 桌遊遊戲條目 ──→ 關聯遊戲清單 ──→ IGDB:Barrage
                                                           │
                                                           └→ 電子遊戲版本／Steam
```

BGG 與 IGDB 是不同外部遊戲身分；即使顯示名稱相同也不合併。若 Steam 版尚未加入收藏庫，關聯遊戲清單保留它的庫外引用；加入後，該引用自動解析為電子遊戲條目。這讓桌遊頁能呈現「Steam 亦可玩」的資訊，同時不把桌遊重度、人數、介紹或貢獻者與電子遊戲版本混在同一筆資料。

## 實作前驗證目標

後續 migration 與 pgTAP 測試至少要證明：

- 並行建立同一 `provider＋source_id` 時，最多只會有一筆外部身分及一個已連結遊戲。
- 資源回收中的遊戲仍佔用其外部身分；還原後原有來源與使用者資料可讀。
- 重新整理來源資料無法修改使用者資料；失敗不清空最後成功快照。
- 同名貢獻者可並存；相同來源身分的貢獻者不可重複。
- BGG 與 IGDB 的同名《Barrage》保持不同外部身分與不同媒介，關聯清單可在庫外與正式遊戲解析之間轉換。
