# Issue 9 行動版核心流程原型計畫

## 問題

在約 390 px 寬的手機上，擁有者能否不迷路地完成「瀏覽或尋找收藏 → 進入遊戲 → 優先上傳多張照片或新增筆記 → 透過來源搜尋確認後新增遊戲」？

## 範圍

- 建立一個不依賴正式技術棧的輕量互動原型，保留在 `prototypes/mobile-core-flows/`。
- 同一頁呈現三個資訊架構假設，並以 URL `?variant=a|b|c` 保存目前變體。
- 以代表性假資料呈現首頁、搜尋／篩選、來源確認、詳情、批次照片和 Markdown 筆記的必要狀態。
- 由 elek 在手機或窄螢幕實際操作後，裁決導覽、批次照片、選填說明、工具列可達性與未儲存狀態。

## 非目標

- 不建立 Next.js、資料庫、驗證、來源 API 或正式元件系統。
- 不驗證 Vditor `ir`，也不把原型程式碼視為正式 UI 實作。

## 假設與驗收

1. 三個變體在空間模型或主要操作上實質不同；切換器、鍵盤切換與網址狀態可用。
2. 每個變體都可走到遊戲詳情；第一輪先依原規格呈現「先選類型」，後續迭代另驗證雙來源搜尋與結果內確認。
3. 詳情頁把「上傳照片」與「新增筆記」置於底部主要操作區；平台、標籤與清單保留次要位置。
4. 照片流程明示可多選、逐檔狀態與上傳後才選填說明；筆記有工具列、儲存狀態與離開未儲存提示。
5. A 的第二輪另驗證「先查詢雙來源，後從結果選擇類型」：A1 依來源分組直接選擇，A2 先以名稱收斂再選呈現形式。
6. A1 的第三輪另驗證「不離開搜尋結果脈絡即可確認並加入」：A1a 在列內漸進展開，A1b 以底部預覽呈現。
7. 以 390 px viewport 實際查看並操作；回報結果只在取得 elek 的真人回饋後寫入議題。

## 裁決結果

- 第一輪採 A「封面書架」：以封面網格為首頁，保留可回到原位置的全頁詳情與底部主要操作。
- 第二輪採 A1：新增時先同時搜尋 BoardGameGeek 與 IGDB，再依來源／遊戲類型分組呈現結果。
- 第三輪採 A1a：點擊結果後在原列內漸進展開辨識資訊，確認無誤即可直接按「加入收藏庫」，不另開確認頁或底部預覽。
- 保留原有建立不變式：點擊結果不等於建立；送出時重新取得來源資料、比對已確認辨識欄位並檢查「供應商＋來源 ID」唯一性。

## 驗證

1. `node --check prototypes/mobile-core-flows/app.js`
2. `python3 -m http.server 4173 --directory prototypes/mobile-core-flows` 後，以瀏覽器在 390 px 寬操作三個 URL。
3. 收集 elek 依票面五項問題的回饋，才關閉「驗證行動版核心流程」。
