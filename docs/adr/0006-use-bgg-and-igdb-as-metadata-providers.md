# ADR 0006：以 BGG 與 IGDB 作為主要中繼資料來源

- 狀態：已接受
- 日期：2026-08-24

## 背景

MVP 必須讓擁有者搜尋遊戲後直接建立條目並自動帶入封面與中繼資料，同時涵蓋桌遊與電子遊戲。候選來源在覆蓋、費用、申請方式與授權條款上差異很大。

完整調查見 [遊戲中繼資料 API 調查](../research/game-metadata-api-survey.md)。來源封面的保存方式另由 [ADR 0002](0002-retain-external-cover-images-for-private-use.md) 決定。

## 決策

1. 桌遊以 BoardGameGeek XML API2 作為主要來源。
2. 電子遊戲以 IGDB 作為主要來源。
3. 外部來源找不到或無法使用時，允許只填名稱建立最小條目；MVP 不增加第二個商業資料源作備援。
4. 來源資料保存供應商、來源 ID、原始頁面連結、納入白名單的來源欄位與最後成功同步時間，並與擁有者資料分離。
5. 自訂顯示名稱、自由標籤、筆記、自訂連結、自訂封面與附件不得被來源重新同步覆寫。
6. API 憑證只存在需要串接來源的伺服器端環境 secrets，且不得出現在瀏覽器、版本庫或未遮罩的記錄中。預覽環境預設不取得正式憑證；若需驗證真實整合，只能使用另外核准的非正式環境憑證。
7. 來源封面依 ADR 0002 永久保存於私有 Supabase Storage，並保留來源名稱、來源識別碼及原始頁面連結。
8. 介面保留 BoardGameGeek 與 IGDB 的來源標示及回鏈。

## 理由

- BoardGameGeek 是調查中唯一同時具備廣泛桌遊資料、搜尋與明確非商業 API 授權的可行主來源。
- IGDB 提供電子遊戲搜尋、平台、別名、封面與圖片，非商業使用免費，功能最符合 MVP。
- RAWG 要求每個使用資料的頁面回鏈且永久快取權不明；MobyGames 需要月費，取消後保存權不明；其他候選則已停止、不可用或授權不足。
- BoardGameGeek 禁止修改來源資料，因此來源資料與擁有者覆寫必須明確分層。

## 後果

- BGG 搜尋採「搜尋候選 → 選取 → 取得詳情」兩段流程，並使用後端快取控制請求量。
- IGDB access token 約 60 天失效，後端必須自動更新。
- 供應商沒有繁中資料時，擁有者仍可自訂顯示名稱；搜尋同時涵蓋原文與別名。
- 若未來更換供應商，只替換來源層，不需遷移筆記、標籤、附件與其他擁有者資料。
- 若用途擴大為公開、多人或商業服務，必須重新審查 BoardGameGeek、IGDB 與 Twitch 的現行條款。
